Executive Summary

调研概览与核心结论

六个项目虽形态各异，但共同拼出一条「AI 驱动的内容运营价值链」：从学习对标、校准创作决策，到生产、跨平台发布与商业变现。它们彼此互补，可通过文件系统与统一 Skill 目录（Claude Code / Codex / WorkBuddy）串成工作流。

一句话归类：

  • yyl-benchmark-breakdown（76）—— 竞品/对标「拆解器」：给链接，输出可复用的爆款公式 + 画面口播逐段拆解 + 人设定位（视频多模态级）。
  • cangjie-skill（仓颉）（3,958）—— 高价值内容「蒸馏器」：把书/长视频/播客蒸馏成可被 Agent 直接调用的 Skill 工具包（RIA-TV++ 流水线）。
  • cheat-on-content（5,761）—— 创作「校准系统」：把每次发帖变成盲预测→复盘→进化 rubric 的实验闭环，让直觉可量化。
  • video-publisher-skill（50）—— 发布「执行器」：用浏览器自动化把本地视频准备到四平台草稿并停在发布前，默认不发布（强安全）。
  • AiToEarn（23,969）—— 全链路「平台」：创作→发布→互动→变现一体化智能体平台，是体量最大、最接近产品的项目。
  • ache-chaijie-skill（小红书账号拆解）（8）—— 小红书「账号级拆解器」：给 1–5 个链接，输出账号画像 + 爆款归因 + 真实封面审计 + 对标推荐，自动生成可打开的可视化 HTML 报告。

关键发现：前五个均为「单点 Skill / 工作流」，AiToEarn 是「平台级产品」，二者不在同一抽象层；Skill 类项目彼此可组合，且都与 AiToEarn 的 Publish/Create 环节存在能力重叠或互补空间。其中 yyl-benchmark-breakdown 与 ache-chaijie-skill 同为「拆解类」但分层不同：前者是视频多模态（画面 + 口播）级，后者是小红书账号 / 封面级，二者均可作为 cheat-on-content 的基准输入（通过 cheat-learn-from 导入）。

yyl-benchmark-breakdown

github.com/ttfake92-lab/skills · skills/yyl-benchmark-breakdown
76· 12 forks 丢一个链接，把对标内容拆到「能复用」的程度

一、基础信息

GitHub 地址：ttfake92-lab/skills/blob/main/skills/yyl-benchmark-breakdown/SKILL.md

项目定位：国内短视频多模态对标拆解 Agent Skill，核心职能为抓取平台内容、多模态解析、生成可复用爆款模板、本地归档竞品样本库

核心关键词：竞品拆解、多模态解析、短视频爬虫、画面口播对齐、benchmark 样本库

二、核心完整工作流（8 阶段标准化执行）

1前置依赖自检：自动校验 Docker、ffmpeg、Whisper、Douyin_TikTok_Download_API、XHS-Downloader，缺失自动输出安装命令
2链接识别分层：自动区分抖音 / 小红书 / B 站 / YouTube / 公众号，区分单条内容 / 整账号批量解析
3素材自动采集流水线：Docker 拉起本地爬虫 API，下载无水印视频 / 图文，ffmpeg 提取音轨
4多模态处理：Whisper 中文语音转完整口播稿，视频场景抽帧生成 Contact Sheet 视觉拼图
5四级降级抓取策略：本地爬虫 API → TikHub 海外中转 → Jina 网页解析 → 用户手动粘贴兜底，无强制报错
6双层拆解逻辑：
  • 单条视频：时间轴对齐画面 + 口播，拆解钩子、节奏、CTA、视觉符号
  • 账号批量：抓取 5–15 条样本，提炼固定选题、视觉矩阵、差异化人设
7标准化三件套输出：可复用爆款公式、画面口播逐帧拆解报告、账号人设定位文档
8自动持久归档：报告 + 素材存入 benchmarks/[平台-账号]/ 目录，构建长期竞品基准库

三、强制铁律（项目核心约束）

✅ 依赖自检通过后全自动执行，无需用户二次确认
✅ 短视频必须同时具备完整口播文稿 + 视觉抽帧证据，禁止仅靠封面文案分析
✅ 报告末尾强制附完整转录原文，禁止只输出摘要
✅ 输出导向「可复用模板」，而非单纯复述竞品内容
✅ 所有拆解素材本地持久化，构建可迭代行业基准库

四、技术依赖清单

Docker Desktop（必需） ffmpeg（必需） openai-whisper（必需） Douyin_TikTok_Download_API（必需） XHS-Downloader（必需） TikHub API（可选·海外兜底） Jina Reader（可选·公众号图文）

五、适用场景与边界

适用场景：短视频矩阵运营、数字人账号对标调研、赛道爆款模板提取、新账号前期选题参考、竞品差异化分析

能力边界：

  • 仅做内容调研分析，无脚本生成、内容打分、多平台发布、流量数据复盘能力
  • 仅输出 Markdown 拆解报告，不支持直接产出短视频 / 图文成品
  • 依赖本地 Docker 爬虫，无云端开箱能力，初次部署环境复杂度高

六、项目优势

✅ 国内短视频平台原生适配，完整覆盖图文 / 短视频双形态
✅ 业内独有的画面 + 口播时间轴对齐拆解体系，兼顾视觉与文案双维度
✅ 四级抓取降级策略，容错率极高，不会因链接失效中断工作流
✅ 标准化归档机制，长期沉淀可复用行业竞品数据库

cangjie-skill（仓颉技能）

github.com/kangarooking/cangjie-skill
3,958· 542 forks 读完、看完、听完，带走一套能调用的方法论

一、基础信息

GitHub 地址：github.com/kangarooking/cangjie-skill

项目定位：长文本知识蒸馏工具链，将书籍、课程、播客、长视频文稿提炼为 AI Agent 可独立调用的标准化 Skill 包

核心关键词：RIA-TV++ 蒸馏流水线、三重验证、知识结构化、方法论提取、书本转 AI 工具

二、核心技术：RIA-TV++ 六阶段蒸馏流水线

①Adler 全书整体分析：分层拆解书籍结构、核心论点、适用场景，输出 BOOK_OVERVIEW.md 全局图谱
②五路并行提取器：同步抽取框架、原则、实战案例、反例、专业术语，批量产出候选方法论单元
③三重验证筛选（核心质控）：
  • 跨域佐证：原文至少 2 处独立内容支撑
  • 预测能力：可解决原文未覆盖的全新场景
  • 非常识过滤：剔除大众基础认知内容
  • 筛选通过率仅 25%–50%，严格过滤无效知识
④RIA++ 六维结构化封装：R 原文引用 / I 释义 / A1 书中案例 / A2 业务触发场景 / E 可执行步骤 / B 适用边界
⑤Zettelkasten 知识网络：梳理 Skill 之间依赖、组合、对立关系，生成 INDEX.md 技能地图
⑥压力测试交付：构造诱饵测试用例校验触发精度，输出可直接导入 Claude 的完整 Skill 仓库

三、预置成熟 Skill 资产库

已完成 20+ 经典内容蒸馏，覆盖商业、投资、营销、中医、社科：巴菲特致股东信、《穷查理宝典》《影响力》《爆款文案》《黄帝内经》《毛选》《孙子兵法》等，每个著作输出 10–25 个独立可调用 Skill。

四、生态联动体系

同作者三大协同项目：

项目职能

cangjie-skill蒸馏书籍 / 课程标准化方法论（本项目）
darwin-skill自动迭代优化已有 Skill 的执行精度

五、适用场景与边界

适用场景：内容创作底层理论支撑、商业决策分析、文案写作框架沉淀、短视频爆款逻辑提炼、长期知识资产数字化

能力边界：

  • 无短视频爬虫、视频解析、竞品抓取能力，不直接处理短视频链接
  • 仅输出理论方法论 Skill，不具备内容打分、发布、流量复盘等运营功能
  • 输入素材仅限纯文本（书籍、字幕文稿、播客文字），无法直接解析视频文件

六、项目优势

✅ 独创三重验证质控机制，规避 AI 提炼碎片化、无效知识
✅ 标准化 Skill 输出格式，无缝对接 Cursor/Claude 所有内容工具
✅ 知识网络化设计，支持多技能组合联动解决复杂创作需求
✅ 大量成熟预置技能包，开箱即可用于文案、选题、商业分析

cheat-on-content

github.com/XBuilderLAB/cheat-on-content
5,761· 835 forks 把每次发帖变成可校准的实验

一、基础信息

GitHub 地址：github.com/XBuilderLAB/cheat-on-content

项目定位：短视频创作者全链路自进化内容实验闭环 Skill 套件，核心目标把「凭感觉创作」转为「数据校准式内容实验」

核心关键词：自进化评分标尺、盲预测机制、T+3 数据复盘、内容实验闭环、账号专属爆款公式

二、核心业务闭环（标准化五步实验流程）

1草稿量化打分（cheat-score）：基于账号历史数据、行业基准对标，对脚本、封面、标题进行多维度量化评分
2不可篡改盲预测（cheat-predict）：发布前强制记录播放、互动预测值，系统钩子锁定记录，杜绝事后修改
3内容发布登记（cheat-shoot/cheat-publish）：记录素材、发布渠道、排期，维护内容产能缓冲区
4T+3 天数据复盘（cheat-retro）：自动抓取平台真实播放、点赞、转化数据，对比预测偏差定位内容缺陷
5评分标尺迭代（cheat-bump）：连续三次预测偏差自动触发标尺升级，升级前全量重校验历史样本，确保精度提升才生效

三、内置子 Skill 体系

子技能核心功能
cheat-init项目初始化，生成目录与本地知识库
cheat-learn-from从对标账号导入 script + 数据，拆解 pattern 并派生基准信号（不限于 yyl）
cheat-score多维度内容质量打分
cheat-predict发布前盲流量预测
cheat-shoot素材拍摄归档、产能缓冲管理
cheat-publish多平台发布记录
cheat-retro流量数据复盘、偏差分析
cheat-bump迭代更新账号专属评分规则
cheat-recommend基于历史爆款推荐选题
cheat-trends抓取平台热点话题

四、三大核心防自欺铁律（项目核心创新）

🔒 盲预测锁死：预测记录写入本地归档，发布后不可修改，规避创作者主观修正数据
🔒 标尺升级全量校验：更新评分规则必须重算全部历史内容，精度优于旧版本方可生效
🔒 精简知识库机制：被数据证伪的创作观察自动删除，仅留存有效判断逻辑

五、适用场景与边界

适用场景：短视频矩阵长期运营、数字人账号数据化迭代、个人 IP 爆款沉淀、批量内容精细化运营、内容工作室标准化流程

能力边界：

  • 无原生竞品抓取、视频拆解能力，必须搭配 yyl-benchmark-breakdown 获取行业基准
  • 无理论方法论提取能力，选题、文案框架依赖 cangjie-skill 提供底层逻辑
  • 不内置多平台发布爬虫，需配套 video-publisher 类分发 Skill 完成上线

六、项目优势

✅ 行业唯一自进化账号专属评估体系，区别通用大模型统一评判标准
✅ 完整内容实验闭环，打通创作 - 发布 - 复盘 - 迭代全链路
✅ 内置强制防主观作弊机制，量化创作直觉，沉淀可复用账号爆款公式
✅ 标准化 MCP 接口，可无缝串联竞品拆解、知识蒸馏、发布类第三方 Skill

8· 0 forks 一句话拆透一个小红书账号

一、基础信息

GitHub 地址：github.com/acheAIsuiyimen/ache-chaijie-skill

项目定位：小红书账号与竞品拆解 Agent Skill。输入 1–5 个账号链接直接分析，或先确认画像（赛道/内容类型/目标用户/转化目标）再推荐对标账号；结合真实封面视觉审计与小红书内容机制，输出爆款归因、可复制公式、选题建议，并自动生成可打开的可视化 HTML 报告。

核心关键词：账号拆解、爆款归因、封面视觉审计、对标账号发现、可视化 HTML 报告、公开数据优先

二、核心能力矩阵

①账号深度拆解：基于真实主页与公开内容，分析定位人设、选题策略、爆款内容模型、封面与标题规律、评论区运营逻辑、商业化路径、内容迭代与当前增长策略——重点回答「这个账号为什么能做起来」。
②智能寻找对标账号：无现成对标时，按赛道/内容类型/目标用户/转化目标自动推荐 2 个成熟标杆 + 3 个当前可对标账号，并明确区分「已验证的小红书主页账号」与「外部搜索待验证账号」，避免错误对标。
③爆款模式识别：识别内容中的有效复用、模板迭代、内容矩阵、机械复制，判断增长来自偶发爆款还是已形成稳定内容系统。
④封面与内容结构分析：直接分析真实笔记样本（封面文案、主体设计、构图、配色、视觉钩子、信任证据、内容结构、评论反馈），避免只看数据不看内容。
⑤账号成长路径还原：当公开样本充足时，还原早期探索 → 内容转折 → 爆发阶段 → 当前稳定打法，理解账号如何一步步跑出来。

三、分析原则（强约束）

✅ 所有结论仅基于公开可验证信息（主页/真实笔记/封面/标题/评论/公开数据），不编造阅读量、流量、转化、商业合作等后台指标
✅ 无法确认的信息明确标注「未公开/未获取」，不臆测
✅ 优先让用户本地浏览器登录授权，不把密码或 Cookie 粘贴进对话/仓库/公开文件，不绕过验证码、权限或平台风控
✅ 首次「无法访问」不当作最终结果，会先排查宿主内置浏览器/Skills/连接器，再推荐外部方案或截图提交

四、输出与运行方式

默认产出：单页 HTML 可视化报告，含账号画像、内容模型分析、爆款案例拆解、成长路径复盘、对标学习建议、三阶段行动路线图；报告中账号/笔记/案例/封面均保留原始链接，可直接跳转访问。

交互模式：

  • 直接分析：给 1–5 个链接即直接开拆，不强制先答定位问题；完成后写 HTML 报告到工作区，聊天只留关键结论。
  • 先找对标：无现成账号时，先问一个高信息量问题并用选择题补齐画像，用户确认后才搜索并给 5 个候选，区分已验证/待验证。
  • 横向对比：支持 2–5 个账号同屏对比、对标账号发现、爆款模式分析。

安装：clone 整个目录放入 Agent 的 skills 目录（入口 SKILL.md）；WorkBuddy 等若支持 GitHub 导入 Skill 可直接导入。可选工具不强制绑定某一插件（Agent-Reach / xiaohongshu-cli / Playwright 任一即可）。

五、技术依赖与边界

Skill 目录运行（轻） xiaohongshu-cli（可选） Playwright（可选） Agent-Reach（可选） 平台 Cookie/登录态（可能影响可用数据）

适用场景：小红书起号对标、竞品账号分析、爆款公式提取、数字人/垂类账号前期选题、内容团队快速学习优秀账号增长逻辑。

能力边界：

  • 仅覆盖小红书单平台，不做抖音/B站/YouTube 等跨平台拆解
  • 账号/封面级拆解，不做视频转写与口播逐帧拆解（那是 yyl-benchmark-breakdown 的领地）
  • 无内容打分、脚本生成、多平台发布、流量数据复盘能力（需搭配 cheat-on-content / video-publisher-skill）
  • 结论质量依赖平台公开数据丰度；登录态/Cookie 缺失时可用样本会减少

六、项目优势

✅ 真实封面视觉审计，不空谈数据——直接读封面文案、构图、配色、视觉钩子
✅ 可视化 HTML 报告开箱即用，原始链接可追溯，降低「结论不可信」风险
✅ 强隐私与安全约束（不绕过风控、不存密码 Cookie），部署轻、无 Docker/重型依赖
✅ 显式区分「已验证站内账号」与「外部待验证」，有效规避错误对标
